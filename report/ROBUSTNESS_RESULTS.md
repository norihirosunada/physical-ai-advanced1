# 配置変動と停止条件の追加評価

## 条件と結果

3点の箱形代理物、配置seed 19・31・73。各配置の各画材を1回ずつ取得する9試行。
各試行前にロボットを退避・停止し、利用者の返却後を模して全画材を置き直す。
指示後は新しい画像を観察し、画像の位置・向きからSO-101で把持・搬送・配置する。
評価用のset_poseは試行間だけに使用し、ロボット搬送中には使わない。
Gazebo正解位置は誤差集計に加え、持ち上げ・保持の確認と停止判断、最終成功判定にも使用する。完全に画像だけの制御ではない。

9試行中7成功、2失敗。限定された条件の実測であり、一般的な成功率とは解釈しない。
消しゴムと赤は各3試行で成功、青は1成功・2失敗。

## 失敗の観察と試した変更

- seed19の青：下降までは到達したが、閉じる際に物体が押し出され、35mmの持ち上げを確認できなかった。
- seed31の青：持ち上げ・水平搬送後、配置下降で目標関節角へ到達せずタイムアウト。この試行では赤の最大XY変位が約40.7mmに達しており、周辺画材を乱した失敗でもある。保持・配置・周辺干渉は未解決。
- seed19の同じ失敗条件に対し、閉じる目標角を弱めて4秒へ延長する設定、さらに既知幅から2mmの把持位置補正を加える設定を試したが、どちらも取得失敗。
- これら2つの調整試行は9条件の集計へ混ぜず、主実装は以前の設定（閉じる目標-0.15rad、2秒、位置補正なし）へ戻した。
- 失敗時は状態をunknownにして以後の搬送を拒否する。記録を保存し、次の独立試行の前に世界と制御ノードを再起動する。

| 受け取り場所に別画材がある | blocked | 0 | 0 |
| 別画材が対象の上に重なる | not_detected | 0 | 0 |

観察用の退避は取得軌道と区別して記録。いずれもexecutingへ移行していない。
未検出時に前のlocationが残っていたため、unknownへ更新する修正を加え、4条件を再確認した。
この4例での停止を確認したもので、一般的な遮蔽や未知障害物の検出保証ではない。

## 記録の扱い

- 初回の評価クライアントのbefore欄には古い受信位置が含まれるため、その欄で物体移動を比較しない。初回の搬送成否はサーバーの物体位置・段階ログによる。
- 更新版は新しいClock・Pose・画像を待ち、動作中の他物体の最大XY変位と発行軌道を監視する。
- seed73の消しゴムと赤は初回に起動待ちで未実施だった。把持失敗に数えず、起動済みの環境で再実行して成功を確認した。
- 起動待ちの評価期限は60秒から180秒へ変更した。待機中にロボット指令は送らない。
- 以前のseed7での6搬送と再配置後の2搬送は、今回の9取得試行とは分ける。

## 次に直すこと

交換・追加の拡張より、細い代理物の把持・保持・配置の安定化を優先する。
同じ位置で向きだけを変える条件、同じ向きで位置だけを変える条件を作り、指先の接触、保持姿勢、閉じる間の関節誤差を切り分ける。
カメラの色・高さ・校正の仮定と箱形モデルの限界は引き続き残る。実画材・実機・利用者の効果は未検証。
