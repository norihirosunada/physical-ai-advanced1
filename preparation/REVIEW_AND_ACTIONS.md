# 進捗の独立レビューと対応

依頼：現在の進捗を独立エージェントが読み取り専用でレビュー。人の利用者・講師による評価ではない。
対象：テーマ、課題要件、実装、9取得と停止4条件のデータ、提出準備。

## 結論

テーマの核は試作できている。把持の一般化と提出物は未完成。
把持の完全化を待って提出準備を止めず、非重複3点・校正済みカメラ・箱形代理物に対象を絞って完成度を上げる。

## 優先指摘

1. seed31の青の失敗では、赤の最大XY変位が約40.7mm。配置下降タイムアウトだけでなく周辺画材を動かした失敗として報告する。
2. 画像推定は搬送元目標の生成に使うが、Gazebo正解位置は実行中の持ち上げ・保持・成功判定にも使用。『評価のみ』『画像だけの制御』とは説明しない。
3. 対象と配置先の中心距離だけでは開いた指や接近軌道の干渉を判定できない。失敗にも物体姿勢・関節目標誤差・段階ごとの周辺変位を残し、実行中に監視する。
4. 9取得7成功・停止4条件の値はデータと整合。ただし各条件1回、初回3件は連続変位記録なし。一般的な成功率・非接触とは解釈しない。
5. 2分程度のROS版デモ、PDF原稿、公開コード構成の準備を今から進める。

## 進める順序と完了条件

| 優先 | 作業 | 完了条件 |
|---|---|---|
| 1 | 報告とシステム説明の訂正 | 40.7mmの周辺移動と、正解情報による実行中監視を明記 |
| 2 | 診断・中断の追加 | roll/pitch/yaw、関節目標誤差、段階別の周辺変位を保存し、5mm超過を途中検出してhold・faultへ |
| 3 | 失敗2条件＋成功1条件の再試験 | 条件を固定し、幾何から導いた修正の前後を比較。失敗も保存 |
| 4 | 再観察の連続デモ | 取得→返却→利用者を模した位置変更→再観察→取得を1つの記録へ |
| 同時進行 | 提出原稿・デモ台本・コード入口 | AI／非AI、簡略化、正解情報、結果と限界が一貫する原稿を作る |
| 5 | 交換 | 核のシナリオが再現できた後、返却＋別画材の取得をまとめる |

優先を下げる：12画材、複数手元スロット、山積み解消、実物の細い鉛筆、汎用MoveIt化、LLM/VLMへの置換、豪華なUI。
動作学習は要件上必須ではない。現在の学習済み文字分類器の学習条件と未学習表現の確認を説明する。
作業を日程目安で止めず、上の完了条件と実測結果に沿って進める。

## 診断仮説（未検証）

従来の開き角0.8radでは可動指が対象中心から大きく横へ張り出す。
近傍の赤へ開いた指が接触し、閉鎖時に周辺物体と保持姿勢が乱れる可能性がある。
既知の22mm以下の箱に必要な開口を幾何から確認し、0.2radの開口で失敗2条件と成功条件を比較する。
これは仮説であり、成功するまで原因確定とは述べない。主実装へ採用するかは再試験後に決める。
